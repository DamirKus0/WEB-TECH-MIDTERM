# Micro-Loan Platform

Учебная платформа микрозаймов. Endterm продолжает существующий midterm: сохраняются бело-синий дизайн, Bootstrap, карточки и адаптивная вёрстка. Добавлены JavaScript и jQuery. Реальные займы, платежи, авторизация и отправка писем не предусмотрены. Используйте только вымышленные персональные данные.

## Запуск

В корне проекта выполните:

```sh
python -m http.server 8000
```

Откройте `http://localhost:8000`. Сборка и установка пакетов для сайта не нужны. Для Bootstrap 5.3.3, Bootstrap Icons 1.11.3 и jQuery 3.7.1 через CDN нужен интернет. Иконки шрифтовые, SVG не используются.

## Что добавлено участником №1

- Главная: условия, этапы подачи заявки и калькулятор $100–$5,000 на 1–24 целых месяца. Результат содержит проценты, общую сумму и ежемесячный платёж.
- Кнопка калькулятора передаёт сумму и срок через `apply.html?amount=1000&term=12`. Изменение полей скрывает старый результат до следующего расчёта.
- Заявка: имя, фамилия, email, сумма, срок, цель и согласие с демонстрационными условиями. Проверка выполняется JavaScript, сообщения выводятся возле полей, фокус переходит к первой ошибке.
- Валидная заявка передаётся в `MicroLoan.addApplication()`. После подтверждённого сохранения выводится ID и pending, повторная отправка блокируется. При ошибке введённые значения сохраняются в форме.
- FAQ: 7 записей из массива, поиск по вопросам и ответам, очистка поиска, пустое состояние, раскрытие ответов через jQuery.
- Общие меню и подвал на трёх endterm-страницах, Bootstrap Grid и собственные breakpoints 768px/576px.

## Зависимость от участника №2

**В этой ветке `js/store.js` ещё отсутствует.** Калькулятор и сохранение заявки подготовлены для общего интерфейса, но до подключения модуля недоступны. Интерфейс показывает понятное сообщение; сохранение и успешная отправка не имитируются. Браузер также может сообщить 404 для отсутствующего `store.js`.

Нужны следующие синхронные методы объекта `window.MicroLoan`:

```js
MicroLoan.calculateLoan(amount, termMonths, annualRate)
// Возвращает { interest, total, monthlyPayment } с числами.

MicroLoan.addApplication(data)
// Возвращает сохранённую запись с уникальным id и status: 'pending'.
// При невозможности сохранения выбрасывает ошибку.
```

Формула расчёта должна находиться только в `js/store.js`:

```text
interest = amount * annualRate * termMonths / 12
total = amount + interest
monthlyPayment = total / termMonths
```

`annualRate` передаётся как `0.05`. Заявка содержит `firstName`, `lastName`, `email`, числовые `amount` и `termMonths`, `annualRate`, допустимый `purpose`, `status: 'pending'`, фактическое время `createdAt` и `disbursedAt: null`. Уникальный ID создаёт модуль данных.

Порядок подключения: Bootstrap CSS → `common.css` → стили страницы; затем `store.js` → `public.js` → `application.js` (на форме). На FAQ: jQuery → `help.js`. Для скриптов используется `defer`.

В `main` уже присутствуют `loans.html`, `loan-details.html`, `css2/style2.css`, `js/data.js`, `js/dashboard.js` и `js/loan-details.js` участника №2. Кабинет показывает демонстрационные займы и фильтр статуса, а детали — образец графика и переключение условий. Ссылки My Loans и Privacy/Terms доступны. Пока отсутствуют `profile.html` и общий модуль `js/store.js`: объединение веток не завершает сквозную интеграцию заявки с кабинетом. Участнику №2 также нужно подключить `css/common.css` перед `css2/style2.css` для одинакового меню и оформления.

## localStorage

По согласованному ТЗ чтением и записью должен управлять участник №2 через `js/store.js`; сейчас этот модуль отсутствует. Планируемые ключи: `microloan.loans.v1` и `microloan.profile.v1`. Данные остаются в текущем браузере и на текущем адресе сайта. Они не отправляются на сервер; очистка хранилища удаляет демонстрационные записи. Обработка повреждённого JSON, пустого списка, уникальных ID и отказа записи относится к модулю данных.

## Код для защиты

Используются обычные `function`, `if/else`, циклы `for`, массивы и DOM. Не используются `Number.isFinite`, `Number.isInteger`, `every`, `forEach`, `includes`, `matchMedia` и регулярное выражение email. Формат email проверяется в JavaScript через свойство `typeMismatch` поля `type="email"`, с собственным сообщением об ошибке.

Несколько дополнительных методов оставлены для конкретных требований ТЗ:

- `URLSearchParams` читает сумму и срок из ссылки калькулятора.
- `toFixed(2)` оставляет два знака после запятой; `trim()` убирает пробелы по краям имени.
- `try/catch` обрабатывает отказ расчёта и сохранения, `toISOString()` задаёт дату в согласованном формате.
- `closest()` и `find()` требуются для FAQ; `stop(true, true)` убирает очередь анимаций.

Это адаптация под уровень лекций, а не обещание, что каждый метод дословно встречается на слайдах.

## Проверка

1. Без `store.js`: откройте Home и убедитесь, что вместо ложного расчёта показана недоступность. Заполните заявку: она не должна сообщать об успешном сохранении. FAQ должен работать независимо.
2. После подключения `store.js`: рассчитайте $1,000 на 12 месяцев. Ожидаются $50.00 процентов, $1050.00 к возврату и $87.50 в месяц.
3. Проверьте суммы 99 и 5001, сроки 0, 25 и 1.5, пустой ввод. Некорректный результат и ссылка с параметрами не должны отображаться.
4. Перейдите к заявке из калькулятора. Сумма и срок должны заполниться. Откройте `apply.html?amount=99&term=1.5`: неверные значения не принимаются.
5. Отправьте пустую форму, затем проверьте короткие имена, email без корректного формата, отсутствие цели и согласия. Исправление ввода должно обновлять ошибки.
6. Сохраните корректную заявку. Должны появиться ID и pending. Повторная отправка не создаёт вторую запись. При отказе хранилища нет сообщения об успехе, значения не теряются.
7. После объединения откройте кабинет и перезагрузите страницу: заявка должна сохраниться. Проверьте все ссылки и сценарии из `docs/testing.md` участника №2.
8. В Help найдите `87.50` (поиск по ответам), введите отсутствующее слово, очистите поиск. Раскройте ответ с клавиатуры и несколькими быстрыми нажатиями.
9. Проверьте страницы на телефоне, планшете и компьютере, фокус клавиатуры и консоль.

При разработке пройдены 79 автоматических проверок интерфейса в jsdom. Для методов `MicroLoan` использовался тестовый объект вне проекта. Это проверка интерфейса, а не реального хранилища, сохранения после перезагрузки или полной интеграции.

В браузере проверены сообщения валидации и фокус на первом неверном поле, поиск FAQ по ответам, пустой поиск, очистка и раскрытие с клавиатуры. Проверена адаптивная сетка. Полный сценарий и отсутствие всех сетевых ошибок требуют подключения файлов участника №2.
